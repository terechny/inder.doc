9. Чем отличаются ключевые слова: include и require, mysql_connect и mysql_pconnect?

    include включает и выполняет указанный файл.	
    require аналогично include, за исключением того, 
    что в случае возникновения ошибки он также выдаст фатальную ошибку уровня E_COMPILE_ERROR. 
    Другими словами, он остановит выполнение скрипта, 
    тогда как include только выдал бы предупреждение E_WARNING, 
    которое позволило бы скрипту продолжить выполнение.	
    mysql_pconnect() работает аналогично mysql_connect() с двумя важными отличиями.
    Во-первых, при соединении функция пытается найти уже открытый (постоянный) 
	указатель на тот же сервер с тем же пользователем и паролем. 
	Если он найден, возвращён функцией будет именно он, вместо открытия нового соединения.
	Во-вторых, соединение с SQL-сервером не будет закрыто, когда работа скрипта закончится. 
	Вместо этого, оно останется рабочим для будущего использования (mysql_close() 
	также не закрывает постоянные соединения, открытые mysql_pconnect()).
	Соединения такого типа называют 'постоянными'.

15. Что такое генераторы и как их использовать?

	Генератор предоставляет функцию, которая генерирует набор значений.
	Для возвращения значения из функции применяется оператор yield. 
	Но в отличие от return оператор yield сохраняет состояние функции, 
	позволяя ей продолжать работу с того места, когда остановилось ее выполнение.
	
	Генератор позволяет вам писать код, использующий foreach для перебора набора данных 
	без необходимости создания массива в памяти, что может привести к превышению лимита памяти, 
	либо потребует довольно много времени для его создания. 
	Вместо этого, вы можете написать функцию-генератор, которая, по сути, является обычной функцией, 
	за исключением того, что вместо возврата единственного значения, 
	генератор может возвращать (yield) столько раз, сколько необходимо для генерации значений, 
	позволяющих перебрать исходный набор данных.

21. Расскажите об обработке ошибок и исключения (try catch, finaly и throw).

	Модель исключений (exceptions) в PHP похожа с используемыми в других языках программирования. 
	Исключение можно сгенерировать (выбросить) при помощи оператора throw, 
	и можно перехватить (поймать) оператором catch. Код генерирующий исключение, 
	должен быть окружён блоком try, для того, чтобы можно было перехватить исключение. 
	Каждый блок try должен иметь как минимум один соответствующий ему блок catch или finally.

	В случае, если выброшено исключение, для которого нет блока catch в текущей функции, 
	это исключение будет "всплывать" по стеку вызова, пока не будет найден подходящий блок catch. 
	При этом, все встреченные блоки finally будут исполнены. 
	Если стек вызовов раскрутится до глобальной области видимости, не встретив подходящего блока catch, 
	программа завершит работу с фатальной ошибкой, если только у вас не настроен глобальный 
	обработчик исключений.

24. Сравнение значений переменных в РНР и подводные камни? Приведение типов. Что изменилось в PHP 8 в этом контексте?	

    В PHP 5 и более ранних версиях при сравнении значений переменных разных типов происходило автоматическое приведение типов. 
    Например, при сравнении числа и строки PHP пытался преобразовать строку в число и затем сравнивал их значения. 
    Начиная с PHP 8 были внесены изменения в контексте приведения типов при сравнении значений переменных. 
    В PHP 8 появилась строгость типов (strict typing), 
    которая позволяет более точно контролировать приведение типов при сравнении. 
    Теперь PHP не будет автоматически преобразовывать типы данных при сравнении значений переменных разных типов. 
    Если типы несовместимы, будет выброшена ошибка.
    Например, если в PHP 8 производится сравнение числа и строки, будет выброшена ошибка, так как эти типы данных несовместимы. 
    Для сравнения значений разных типов необходимо явно привести их к одному типу или использовать функции сравнения, 
    которые учитывают разные типы данных.

36. Расскажите о Dependency Injection: что такое DI-контейнеры? Какие есть варианты реализаций?

    Dependency Injection (DI) - это паттерн программирования, который позволяет управлять зависимостями между объектами. 
    Он основан на принципе инверсии управления (Inversion of Control, IoC), 
    который предлагает перенести ответственность за создание и управление объектами из классов, которые их используют, в отдельный механизм.

    DI-контейнеры являются инструментами, которые облегчают внедрение зависимостей в приложении. 
    Они предоставляют механизм для автоматического создания и связывания объектов, основываясь на их зависимостях.

    Существует несколько вариантов реализаций DI-контейнеров:

    1. Конструкторная инъекция зависимостей: в этом случае зависимости передаются через конструктор класса. 
       Контейнер создает экземпляр класса и автоматически передает необходимые зависимости через его конструктор.

    2. Сеттерная инъекция зависимостей: в этом случае зависимости передаются через сеттеры (методы установки). 
       Контейнер создает экземпляр класса и автоматически вызывает соответствующие сеттеры для передачи зависимостей.

    3. Инъекция зависимостей через интерфейсы: в этом случае классы объявляются с интерфейсами, 
       а контейнер связывает интерфейсы с их реализациями. 
       При создании экземпляра класса, контейнер автоматически подставляет правильную реализацию зависимости.

    4. Автоматическая инъекция зависимостей: в этом случае контейнер анализирует 
       аннотации или другую метаинформацию в коде и автоматически определяет зависимости для классов.

       Каждый из этих вариантов имеет свои преимущества и может быть использован в зависимости от конкретных требований приложения. 
       DI-контейнеры помогают упростить управление зависимостями, 
        повысить гибкость и переиспользуемость кода, а также улучшить тестируемость приложения.

38. Что вам известно о шаблонах GoF?

    Порождающие паттерны — абстрагируют процесс инстанцирования или, иными словами, процесс порождения классов и объектов.

    Абстрактная фабрика (Abstract Factory)

	Среди подобных шаблонов можно выделить следующие:

39. Что вам известно о шаблонах, которые применяются в ORM?

    ORM (Object-Relational Mapping) - это техника программирования, 
    которая позволяет связывать объекты в языке программирования с записями в реляционной базе данных. 
    ORM-фреймворки предлагают различные шаблоны и подходы для работы с базой данных.

    Некоторые из шаблонов, которые применяются в ORM, включают:

    1. Активная запись (Active Record): этот шаблон предлагает связать каждый объект с записью в базе данных. 
       Объекты содержат методы для сохранения, обновления и удаления записей, а также для выполнения запросов к базе данных.

    2. Сессия данных (Data Mapper): в этом шаблоне объекты не содержат логики доступа к базе данных. 
       Вместо этого, отдельный компонент, называемый маппером данных, отвечает за сохранение и загрузку объектов из базы данных.

    3. Единица работы (Unit of Work): этот шаблон предлагает группировать операции с базой данных в единую транзакцию. 
       Объект "единица работы" отслеживает все изменения объектов и выполняет соответствующие операции при фиксации транзакции.

    4. Ленивая загрузка (Lazy Loading): это шаблон позволяет отложить загрузку связанных объектов до момента, 
       когда они действительно потребуются. Это помогает улучшить производительность при работе с большими объемами данных.

    5. Каскадное сохранение (Cascade Saving): этот шаблон позволяет автоматически сохранять связанные объекты при сохранении родительского объекта. 
       Это упрощает процесс сохранения связанных данных и предотвращает несогласованность в базе данных.

    Это только некоторые из шаблонов, которые могут быть применены в ORM. 
    Конкретные фреймворки могут предлагать различные комбинации 
    и вариации этих шаблонов в зависимости от своих особенностей и целей.

44. Расскажите о SSH-протоколе.

    SSH — это Secure Shell (безопасная оболочка); это специальный протокол для передачи данных в безопасном режиме. 
    Он очень часто применяется для удаленного управления компьютерами и устройствами по сети.

    Протокол SSH — это то, что дает следующие возможности:
    можно подключаться к удаленному компьютеру и работать с ним через командную строку;
    возможно осуществить шифрование данных, применяя различные алгоритмы;
    он передает любые данные по зашифрованному каналу, в том числе и аудио- или видеофайлы;
    может сжать файлы для их дальнейшего шифрования и транспортировки по сети;

    Суть SSH сводится к тому, что между устройствами проецируется так называемый SSH-туннель: 
    на одном конце данные шифруются и отправляются, а на другом конце — принимаются и расшифровываются. 
    По туннелю данные передвигаются зашифрованными.

    обеспечивает надежную транспортировку данных и предотвращает 
    несанкционированное подключение к каналу передачи информации с целью ее перехвата.

    1. JIT-компилятор (Just-In-Time): В PHP 8 появился экспериментальный JIT-компилятор, 
       который может улучшить производительность PHP-приложений, особенно для интенсивных вычислений и больших проектов.

    2. Новые типы аргументов и возвращаемых значений функций: 
       В PHP 8 добавлены возможности для указания строгих типов аргументов и возвращаемых значений функций, 
       таких как int, string, array и другие. Это помогает улучшить надежность и понимание кода.

    3. Nullsafe оператор: PHP 8 включает оператор "nullsafe" 
       (??) для удобной проверки наличия значения null перед доступом к свойствам или методам объектов.

    4. Атрибуты и метаданные: В PHP 8 появились атрибуты, 
       которые позволяют добавлять метаданные и аннотации к классам, методам и другим элементам кода.

    5. Совместимость с Union Types: PHP 8 предоставляет объединение типов (union types), 
       которые позволяют указывать, что переменная может иметь несколько типов значений.

    6. Прочие улучшения производительности: 
       В PHP 8 были внесены множественные улучшения производительности, включая оптимизации внутреннего движка языка.

    7. Импорт функций через use statement: PHP 8 позволяет импортировать 
       функции из пространства имен с использованием оператора use, аналогично импорту классов и констант.

    8. И многое другое: PHP 8 также включает ряд других новых функций и улучшений, 
       таких как выражение match, изменение поведения оператора `implode()`, новые встроенные функции и другие усовершенствования.

51. Есть ли разница между одинарными и двойными кавычками?

57. Что такое вариативная функция или splat-оператор?

    В PHP вариативная функция (или также называемая splat-оператором) позволяет передавать

61. Что такое stateless?

	Stateless (без сохранения состояния) - это принцип разработки, 
    при котором сервер не сохраняет информацию о предыдущих запросах клиента. 
    Каждый запрос рассматривается независимо от предыдущих запросов, 
    и вся необходимая информация для обработки запроса передается в самом запросе.

62. SOAP vs REST. В чем разница?

    SOAP (Simple Object Access Protocol) и REST (Representational State Transfer) - это два разных подхода к построению веб-сервисов. 

    SOAP использует XML для обмена данными и имеет строгую спецификацию для описания веб-сервисов
    REST использует HTTP-протокол и может использовать различные форматы данных, такие как JSON или XML.
    REST более гибкий и простой в использовании, в то время как SOAP предлагает больше возможностей и расширений.

65. Класс содержит свойство, которое, в свою очередь, является объектом. 
    Что будет содержать это свойство в клонированном объекте: ссылку на тот же дочерний объект или копию дочернего объекта? 
    Что нужно сделать, чтобы это изменить?

    Если свойство класса является объектом, то в клонированном объекте будет содержаться ссылка на тот же дочерний объект, 
    а не его копия. Чтобы изменить это поведение и создать копию дочернего объекта, 
    необходимо реализовать метод __clone() в классе и явно скопировать свойство объекта.

67. Опишите реализацию одного из шаблонов проектирования.

	Примером шаблона проектирования может быть шаблон "Наблюдатель" (Observer). 
        В этом шаблоне есть объект, называемый "субъектом", который содержит список зависимых объектов, 
        называемых "наблюдателями". 
        Когда состояние субъекта изменяется, он уведомляет всех своих наблюдателей, чтобы они могли выполнить определенные действия. 
        Этот шаблон позволяет реализовать слабую связь между объектами и упрощает добавление новых наблюдателей без изменения субъекта.

	В Redis и Memcached данные хранятся в оперативной памяти сервера.

    Оба этих инструмента предоставляют простой интерфейс для работы с данными, такие как установка и получение значений по ключу,
	а также операции со списками, множествами, хэшами и другими структурами данных.

70. Расскажите о целесообразности применения Redis / Memcached для кэширования. Каковы плюсы и минусы?

	Целесообразность применения Redis / Memcached для кэширования заключается в том, 
        что они предоставляют быстрое хранение и доступ к данным, 
        что позволяет значительно увеличить производительность приложения. 

	Плюсы использования Redis / Memcached для кэширования:
	- Быстрый доступ к данным: данные хранятся в оперативной памяти, что обеспечивает низкую задержку при доступе к ним.
	- Масштабируемость: Redis / Memcached позволяют создавать кластеры, что позволяет обрабатывать большой объем запросов 
          и распределять нагрузку между узлами.
	- Гибкость: Redis / Memcached предоставляют различные возможности для кэширования данных, 
          такие как установка времени жизни кэша, использование ключей и т.д.
	- Поддержка различных типов данных: Redis / Memcached позволяют хранить различные типы данных, такие как строки, списки, хэши и т.д.

	Минусы использования Redis / Memcached для кэширования:
	- Ограниченный объем памяти: так как данные хранятся в оперативной памяти, объем доступной памяти может быть ограничен.
	- Возможность потери данных: при сбое системы или перезапуске сервера данные, хранящиеся в кэше, могут быть потеряны.
	- Сложность настройки и управления: Redis / Memcached требуют дополнительной настройки и управления, 
          что может потребовать дополнительных усилий от разработчиков.

71. Назовите различия между nginx и Apache.

	Основные различия между серверами nginx и Apache:

	- Архитектура: nginx работает по событийной модели, что позволяет обрабатывать большое количество одновременных подключений 
                   без создания отдельного потока для каждого подключения. 
          Apache же работает по модели "один процесс - одно соединение", 
          что может привести к проблемам с производительностью при большом количестве одновременных подключений.

	- Производительность: благодаря своей архитектуре, nginx обычно работает быстрее и эффективнее, особенно при обработке статических файлов. 
                          Apache же имеет более широкий набор возможностей и может быть лучшим выбором для обработки динамического контента.
	- Конфигурация: конфигурация nginx основана на простых и понятных директивах, что делает его более легким для настройки. 
                    Конфигурация Apache может быть более сложной и громоздкой.
	- Модульность: Apache имеет большое количество модулей, которые позволяют расширять его функциональность. 
                   Nginx также поддерживает модули, но их количество и разнообразие меньше.

72. Что такое Opcash? Как он работает?

	Opcache (также известный как Zend Opcache) - это модуль PHP, который предназначен для кэширования скомпилированного байт-кода PHP. 
        Opcache ускоряет выполнение PHP-скриптов, уменьшая время, затрачиваемое на компиляцию и загрузку файлов. 

	Opcache работает следующим образом:
	- При первом запуске скрипта, Opcache компилирует его в байт-код и сохраняет его в памяти.
	- При последующих запросах к этому скрипту, Opcache проверяет, есть ли уже скомпилированный байт-код в памяти. 
          Если да, то он загружает его и выполняет скрипт без необходимости повторной компиляции.
	- Если скрипт был изменен, Opcache обнаруживает это и перекомпилирует его перед выполнением.

73. Что такое JIT? Как он работает?

	JIT (Just-In-Time) компиляция - это метод оптимизации исполнения программного кода, 
        при котором код компилируется в машинный код непосредственно перед его выполнением. 
        В отличие от традиционной компиляции, при которой весь код компилируется заранее, 
        JIT компиляция позволяет выполнять оптимизацию кода на основе информации, полученной во время его выполнения.

	JIT компиляция работает следующим образом:
	- При запуске программы, JIT-компилятор анализирует код и определяет участки, которые могут быть оптимизированы.
	- Когда исполнение доходит до такого участка кода, JIT-компилятор компилирует его в машинный код и заменяет исходный код на скомпилированный.
	- После этого, при каждом выполнении этого участка кода, будет использоваться скомпилированный машинный код, 
          что может значительно ускорить выполнение программы.

74. Зачем нужно ключевое слово final?

	Ключевое слово final в PHP используется для указания, что класс, 
        метод или свойство не может быть переопределены или изменены в дочерних классах. 

	Когда класс объявлен как final, он не может быть расширен другими классами. 
        То же самое относится и к методам и свойствам - они не могут быть переопределены или изменены в дочерних классах.

	Использование ключевого слова final может быть полезным, когда требуется защитить определенные части кода от изменений или переопределения, 
        чтобы гарантировать их стабильность и неприкосновенность.

89. Что такое TDD?

	TDD (Test-Driven Development) - это методология разработки программного обеспечения, 
    которая основывается на написании тестов перед написанием кода.

    затем пишет минимальный код, который позволяет пройти эти тесты, и затем улучшает и расширяет код, 
    чтобы удовлетворить все требования. TDD способствует созданию хорошо протестированного и легко поддерживаемого кода.

90. Чем отличаются модульные тесты от интеграционных?

	Модульные тесты направлены на проверку отдельных модулей или компонентов программы. 
    Они обычно выполняются в изоляции от других модулей и могут использовать моки или заглушки для замены зависимостей. 
    Модульные тесты помогают обнаружить ошибки на ранних стадиях разработки и обеспечивают надежность отдельных компонентов.

	Интеграционные тесты, напротив, проверяют взаимодействие между различными модулями или компонентами программы. 
    Они проверяют, как компоненты взаимодействуют друг с другом и с внешними системами.
    Интеграционные тесты могут быть более сложными в настройке и выполнении, но они позволяют выявить проблемы,
    которые могут возникнуть только при работе нескольких компонентов вместе.

91. Что такое трейты? Как применять на практике?

	Трейты (traits) в PHP - это механизм, который позволяет повторно использовать код в классах, не создавая наследования. 
    Трейты представляют собой набор методов, которые могут быть включены в класс с помощью оператора use.

	Трейты полезны, когда необходимо добавить общую функциональность к нескольким классам без создания иерархии наследования. 
    Например, если у вас есть несколько классов, которые должны иметь одинаковые методы для работы с базой данных, 
    вы можете создать трейт с этими методами и затем включить его в каждый класс с помощью оператора use. Это упрощает поддержку и обновление кода.

92. Как разрешить конфликты при использовании trait?

	При использовании трейтов может возникнуть конфликт имен методов, если класс, использующий трейт, уже определяет метод с таким же именем. 
    В таком случае можно разрешить конфликт путем переопределения метода в классе или с помощью псевдонимов.

	Для переопределения метода в классе нужно просто определить его снова с новой реализацией. 
    Таким образом, метод из трейта будет заменен методом из класса.

	Для использования псевдонимов можно использовать оператор as при импортировании трейта. 
    Например, если у трейта есть метод foo(), а класс уже имеет метод с таким же именем, 
    можно использовать оператор as для создания псевдонима для метода из трейта. Например, use MyTrait { foo as traitFoo; }.

93. Как работает автозагрузка классов?

    Эта функция регистрирует одну или несколько функций, которые будут вызываться автоматически при попытке использования неопределенного класса. 
    В этих функциях можно определить правила для поиска и подключения файлов с определениями классов.
	Например, можно создать функцию autoload(), которая будет искать файлы с определениями классов 
    в заданных директориях и подключать их при необходимости. 
    Затем эту функцию можно зарегистрировать с помощью spl_autoload_register().

95. Расскажите о Unit Tests (required), Functional Tests (optional). Моки и стаб в PHP.

	Unit Tests (тесты модулей) - это тесты, которые проверяют отдельные модули или компоненты программы на корректность и соответствие требованиям. 
    Они выполняются в изоляции от других модулей и могут использовать моки или заглушки для замены зависимостей. 
    Unit tests обеспечивают надежность отдельных компонентов программы.

	Functional Tests (функциональные тесты) - это тесты, которые проверяют функциональность системы в целом. 
    Они проверяют взаимодействие между различными модулями и компонентами программы, а также с внешними системами. 
    Functional tests могут быть более сложными в настройке и выполнении, 
    но они позволяют выявить проблемы, которые могут возникнуть только при работе нескольких компонентов вместе.

	Моки (mocks) и стабы (stubs) - это объекты, которые используются в тестировании для замены реальных зависимостей 
    и контроля поведения системы во время выполнения тестов. 
    Моки обычно используются для проверки взаимодействия с внешними системами или сервисами, 
    а стабы - для предоставления фиксированных ответов или данных.

96. Представим ситуацию, в которой нам нужно вызвать частный метод. Как это сделать?

    В PHP нет прямого способа вызвать частный метод извне класса. 
    Частные методы предназначены только для использования внутри класса и не должны быть доступны извне. 
    Это делается для обеспечения инкапсуляции и безопасности кода.

	Однако, если очень нужно вызвать частный метод для тестирования или отладки, можно использовать рефлексию. 
    Рефлексия позволяет анализировать и изменять структуру и поведение классов во время выполнения программы.

	С помощью рефлексии можно получить доступ к частному методу и вызвать его, используя методы класса ReflectionMethod. Например:

	php
	$reflectionClass = new ReflectionClass('MyClass');
	$reflectionMethod = $reflectionClass->getMethod('privateMethod');
	$reflectionMethod->setAccessible(true);
	$reflectionMethod->invoke($object, $arg1, $arg2);

	Где 'MyClass' - имя класса, 'privateMethod' - имя частного метода, $object - объект класса, $arg1, $arg2 - аргументы метода.

	Однако стоит помнить, что вызов частных методов через рефлексию нарушает инкапсуляцию и может привести к неожиданным побочным эффектам. 
    Поэтому такой подход следует использовать с осторожностью и только в особых случаях.

97. Опишите разницу между PHP-FPM и PHP на сокете.

	PHP-FPM (FastCGI Process Manager) и PHP на сокете - это два различных способа запуска PHP-скриптов на веб-сервере.

	PHP-FPM является отдельным процессом, который запускается и управляется веб-сервером (например, Nginx или Apache). 
    Он предоставляет более эффективный способ обработки PHP-скриптов, 
    так как может кэшировать скомпилированный байт-код и обрабатывать несколько запросов одновременно. 
    PHP-FPM работает через протокол FastCGI и обеспечивает более высокую производительность и масштабируемость.
	PHP на сокете - это способ запуска PHP-скриптов, который работает напрямую через сокеты. 
    В этом случае PHP-скрипт выполняется в рамках текущего процесса веб-сервера и не требует дополнительных процессов или служб. 
    Однако, такой подход может быть менее эффективным и масштабируемым, особенно при обработке большого количества запросов.
	Оба подхода имеют свои преимущества и недостатки, и выбор между ними зависит от конкретных требований и условий работы сервера.

    Он представляет собой инструкцию, которая задает конкретное действие, которое должно быть выполнено. 
    Каждая операция имеет свой уникальный opcode, который определяет, какую операцию нужно выполнить и какие данные использовать. 
    Процессоры используют opcode для интерпретации и выполнения инструкций программы.

106. Как вы понимаете REST?

	REST (Representational State Transfer) - это архитектурный стиль, который используется для разработки распределенных систем, таких как веб-сервисы. 
    Он определяет набор принципов и ограничений, которые позволяют создавать масштабируемые, гибкие и легко поддерживаемые системы.

	REST основан на принципе клиент-серверной архитектуры, где клиент отправляет запросы на сервер, а сервер возвращает ответы. 
    Каждый запрос в REST должен быть без состояния, то есть сервер не должен хранить информацию о предыдущих запросах клиента. 
    Вместо этого, клиент должен предоставлять все необходимые данные в каждом запросе.
	REST также использует HTTP протокол для обмена данными между клиентом и сервером. 
    Он определяет различные методы HTTP запросов, такие как GET, POST, PUT и DELETE, которые соответствуют разным операциям над ресурсами на сервере. 
    Ресурсы в REST представляются в виде URL-адресов (Uniform Resource Locator).

	Основные принципы REST включают использование стандартных методов HTTP, однозначное определение ресурсов через URL, 
    использование гипермедиа для связи между ресурсами и возможность кэширования данных для улучшения производительности.

	В целом, REST предоставляет простой и гибкий подход к разработке распределенных систем, 
    который позволяет эффективно обмениваться данными между клиентом и сервером.

107. Что такое Copy-on-write?

	Copy-on-write (COW) - это стратегия оптимизации, которая используется в операционных системах и 
    языках программирования для управления памятью и улучшения производительности. 
    Она позволяет избежать ненужного копирования данных, когда они передаются или изменяются.

	В контексте операционных систем, COW используется при создании копии процесса. 
    Вместо того, чтобы создавать полную копию памяти процесса, COW позволяет общаться между родительским и дочерним процессами до тех пор, 
    пока один из них не попытается изменить общие данные. В этом случае, только тогда происходит фактическое копирование данных.

	В языках программирования, COW используется для оптимизации работы с неизменяемыми объектами или структурами данных. 
    Когда объект или структура передается в функцию или присваивается новой переменной, фактическое копирование данных не происходит. 
    Вместо этого, создается ссылка на оригинальные данные, и только при изменении данных создается их копия.

	Использование COW позволяет снизить потребление памяти и улучшить производительность при работе с большими объемами данных, 
    так как избегается ненужное копирование. Однако, следует быть осторожным при изменении общих данных, 
    так как это может привести к непредсказуемым результатам.

108. Что такое позднее статическое связывание?

	Позднее статическое связывание (late static binding) - это механизм, который позволяет в PHP 
    вызывать статические методы или свойства класса из контекста наследующего класса. 
    Это отличается от обычной статической связывания, где вызывается метод или свойство на основе класса, 
    в котором они были определены.

	В PHP, при использовании позднего статического связывания, ключевое слово "static" 
    внутри метода или свойства ссылается на класс, из которого был вызван метод или свойство, 
    а не на класс, в котором они были определены. 
    Это позволяет динамически выбирать правильный метод или свойство на основе контекста вызова.

	Пример использования позднего статического связывания в PHP:

	php
	class ParentClass {
	    public static function sayHello() {
	        echo "Hello from ParentClass!";
	    }
	    
	    public static function callStatic() {
	        static::sayHello();
	    }
	}

	class ChildClass extends ParentClass {
	    public static function sayHello() {
	        echo "Hello from ChildClass!";
	    }
	}

	ChildClass::callStatic(); // Выводит "Hello from ChildClass!"


	В этом примере, метод callStatic() вызывает метод sayHello() с использованием позднего статического связывания. 
    В результате, будет выведено "Hello from ChildClass!", так как метод sayHello() в классе ChildClass был вызван из контекста класса ChildClass.

	Позднее статическое связывание полезно, когда необходимо динамически выбирать метод или свойство на основе контекста вызова, 
    особенно при работе с наследуемыми классами и переопределением методов.

109. Что такое CQRS?

	CQRS (Command Query Responsibility Segregation) - это архитектурный шаблон, 
    который предлагает разделить операции записи (команды) и операции чтения (запросы) в отдельные модели. 
    Вместо того, чтобы использовать одну модель для обработки как команд, так и запросов, 
    CQRS рекомендует использовать разные модели для каждого типа операций.

	Основная идея CQRS заключается в том, что операции записи и операции чтения имеют разные требования к модели данных. 
    Операции записи обычно требуют высокой производительности, согласованности и мгновенности, 
    поэтому они могут использовать простую структуру данных и оптимизированные механизмы хранения. 
    Операции чтения, с другой стороны, часто требуют сложных запросов и агрегаций данных, 
    поэтому они могут использовать специализированные модели и механизмы хранения.

	Преимущества CQRS:

	1. Улучшенная производительность: разделение операций записи и операций чтения позволяет оптимизировать 
       каждую модель для своих требований, что может привести к улучшению производительности системы в целом.
	2. Гибкость: CQRS позволяет легко вносить изменения в модели команд и запросов независимо друг от друга, 
       что облегчает разработку и поддержку системы.
	3. Масштабируемость: разделение операций записи и операций чтения позволяет масштабировать каждую часть системы независимо, 
       что может быть полезно при работе с большими объемами данных или высокой нагрузкой.

	Однако, использование CQRS также имеет свои сложности и требует дополнительной работы по разработке и поддержке системы. 
    Например, необходимо управлять согласованностью данных между моделями команд и запросов, 
    а также обрабатывать события и обновления данных в разных моделях.

110. Что такое cohesion и coupling? [5]

	Cohesion (согласованность) и coupling (связность) - это два основных понятия в области архитектуры программного обеспечения.

	Cohesion (согласованность) относится к мере, в которой элементы внутри модуля или компонента связаны и сосредоточены на выполнении одной задачи или функции. 
    Высокая согласованность означает, что элементы внутри модуля имеют сильную связь и работают вместе для достижения одной цели. 
    Например, модуль, который отвечает только за обработку платежей, имеет высокую согласованность, так как все его элементы связаны с обработкой платежей.

	Coupling (связность) относится к степени зависимости между модулями или компонентами в системе. 
    Он измеряет, насколько изменение одного модуля может повлиять на другие модули. 
    Низкая связность означает, что модули слабо зависят друг от друга и могут быть изменены независимо. 
    Например, если два модуля имеют низкую связность, изменение одного из них не должно требовать изменений в другом.

	Целью хорошей архитектуры программного обеспечения является достижение высокой согласованности и низкой связности. 
    Это позволяет создавать модули, которые легко понять, изменять и тестировать, а также повышает переиспользуемость и гибкость системы.

111. Как можно получить значение частного свойства класса в рантайме?


	В PHP существует два способа получить значение частного свойства класса в рантайме:

	Использовать рефлексию. Рефлексия - это механизм, который позволяет получить информацию о классах, объектах и свойствах в рантайме. 
    Для получения значения частного свойства класса можно использовать метод getProperty() класса ReflectionProperty.

    -----

	class User {
	    private $name;

	    public function __construct($name) {
	        $this->name = $name;
	    }
	}

	$user = new User('John Doe');

	// Получить значение частного свойства с помощью рефлексии
	$reflectionProperty = new ReflectionProperty('User', 'name');
	$value = $reflectionProperty->getValue($user);

	echo $value; // John Doe

	-----

112. Как можно получить значение частного свойства класса в рантайме без использования рефлексии?

	Использовать замыкание. Замыкание - это функция, которая может ссылаться на переменные из области видимости, в которой она была объявлена. 
    Для получения значения частного свойства класса можно использовать замыкание, которое будет получать значение свойства из объекта.

    ------
	class User {
	    private $name;

	    public function __construct($name) {
	        $this->name = $name;
	    }
	}

	$user = new User('John Doe');

	// Получить значение частного свойства с помощью замыкания
	$reader = function ($object, $property) {
	    return $object->$property;
	};

	$value = $reader($user, 'name');

	echo $value; // John Doe
	-----
