
Архитектура и Ядро (Core)

1. Что такое Service Container?

    Это инструмент для управления зависимостями классов (Dependency Injection). 
    Он знает, как создать объект и какие другие объекты ему нужны для работы.

    Контейнер служб (service container, сервис-контейнер) Laravel – 
    это мощный инструмент для управления зависимостями классов и выполнения внедрения зависимостей. 
    Внедрение зависимостей – зависимости классов «вводятся» в класс через конструктор 
    в виде аргументов или, в некоторых случаях, через методы-сеттеры. 
    При создании класса или вызове методов фреймворк смотрит на список аргументов и, если нужно, 
    создаёт экземпляры необходимых классов и сам подаёт их на вход конструктора или метода.

2. Что такое Service Providers?

    Сервис-провайдеры – это центральное место начальной загрузки всех приложений Laravel. 
    Ваше собственное приложение, а также все основные службы и сервисы Laravel загружаются через них.

    Но, что мы подразумеваем под «начальной загрузкой»?
    В общем, мы имеем в виду регистрацию элементов, включая регистрацию связываний контейнера служб (service container), 
    слушателей событий (event listener), посредников (middleware) и даже маршрутов (route). 
    Сервис-провайдеры являются центральным местом для конфигурирования приложения.

    Laravel использует десятки поставщиков услуг внутренне для инициализации своих основных сервисов, 
    таких как почтовый сервис, очереди, кэш и другие. 
    Многие из этих поставщиков являются “отложенными”, что означает, 
    что они не будут загружены при каждом запросе, 
    а только когда нужны фактические сервисы, которые они предоставляют. 

    Все определенные пользователем поставщики услуг регистрируются в файле bootstrap/providers.php. 
    В этой документации вы узнаете, как писать собственные сервис-провайдеры и регистрировать их в приложении Laravel.

    Это «входные точки» для настройки приложения. 
    В них происходит регистрация связей в контейнере, слушателей событий и маршрутов. 
    Основные методы: register() и boot().

3. Как работают Facades (Фасады)?

   Это статические прокси к классам, хранящимся в Service Container. 
   Они дают удобный синтаксис (например, Cache::get()), скрывая за собой вызов реального объекта.
 
4. Жизненный цикл запроса (Request Lifecycle)?

   public/index.php -> 
   Composer Autoload -> 
   Загрузка приложения (Kernel) -> 
   Регистрация Service Providers -> 
   Прохождение через Middleware -> 
   Роутинг -> 
   Контроллер -> 
   Ответ (Response)

5. В чем разница между bind() и singleton() в контейнере?

   bind() создает новый экземпляр класса при каждом обращении, 
   singleton() создает объект один раз и возвращает его же при последующих вызовах.

6. Что такое Middleware?

   Это слой между запросом и контроллером. 
   Используется для фильтрации (проверка авторизации, логирование, проверка CSRF-токена).

7. Что такое Contracts?

   Это набор интерфейсов, определяющих основные сервисы фреймворка. 
   Они позволяют легко подменять реализации (например, сменить драйвер кэша с Redis на Memcached).
   
Работа с БД (Eloquent & DB)

1. Что такое Проблема N+1 и как её решить?
   
    Это ситуация, когда для списка из N записей делается 1 запрос к основной таблице и еще N запросов к связанным. 
    Решается через Eager Loading — метод with(['relation']).

2. Разница между Lazy Loading и Eager Loading?

    Lazy грузит связанные данные только при обращении к ним (много запросов), 
    Eager грузит всё сразу одним запросом через JOIN или WHERE IN.

3. Что такое Accessors и Mutators?

    Accessors (get...Attribute) преобразуют данные при получении из БД (например, имя с заглавной буквы). 
    Mutators (set...Attribute) преобразуют данные перед сохранением в БД.

4. В чем разница между Query Builder и Eloquent?

    Query Builder — это построитель SQL-запросов (быстрее, возвращает массивы/объекты). 
    Eloquent — это ORM (удобнее, поддерживает связи, события, возвращает модели).

5. Что такое Soft Deletes?

    Это «мягкое удаление». Запись не удаляется из БД, а в поле deleted_at записывается дата. 
    В обычных запросах такие записи игнорируются.

6. Как работают миграции?

    Это система контроля версий для базы данных. 
    Позволяет описывать структуру таблиц в коде и синхронизировать её между разработчиками.

7. Зачем нужны Seeders и Factories?

   Seeders заполняют базу данными (например, админ-аккаунт)
   Factories генерируют фейковые данные (через библиотеку Faker) для тестов.
   
Очереди, События и API

1. Как работают Очереди (Queues)?

   Позволяют отложить выполнение тяжелой задачи (отправка письма, обработка видео) на потом. 
   Нужен драйвер (Redis, Database) и воркер (php artisan queue:work), который будет их выполнять.

2. Что такое API Resources?

   Это слой трансформации моделей в JSON. Позволяет гибко настраивать, 
   какие поля отдавать клиенту, не меняя саму модель.

3. Разница между Gates и Policies?
   
   Gates — для простых проверок (не привязаны к моделям). 
   Policies — логика авторизации для конкретной модели (например, PostPolicy для действий над постами).
   
4. Что такое Laravel Echo?
   
   Инструмент для работы с WebSockets. 
   Позволяет подписываться на каналы и слушать события, транслируемые сервером в реальном времени.

5. Как защититься от CSRF-атак в Laravel?

   Laravel автоматически проверяет CSRF-токен для всех POST/PUT/DELETE запросов. 
   Для форм нужно использовать директиву @csrf.

6. Что такое Dependency Injection (внедрение зависимостей)?

   Это практика, когда класс получает необходимые ему объекты извне (обычно через конструктор), 
   а не создает их сам внутри. Это делает код тестируемым и гибким.
